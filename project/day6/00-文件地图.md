## 三、今天的名词表（10 个，每个都要能一句话说清）

> 规则：先自己写，再对下面的答案。写不出来 = 没会。

| 名词 | 一句话答案 |
| --- | --- |
| **混合检索**（Hybrid Search） | 同时跑向量检索和关键词检索，再把两份结果合起来用 |
| **BM25** | 搜索引擎的老算法：数字面出现次数 + 给稀有词加权 + 长文档打折，**不懂语义** |
| **IDF**（逆文档频率） | 一个词出现在越多文档里就越不值钱；只出现在 1 篇里最值钱 |
| **倒排索引**（inverted index） | 从「词」查「哪几篇文档含它」的索引，BM25 靠它做毫秒级关键词检索（普通数据库是「文档→词」，它是反过来的） |
| **RRF**（倒数排名融合） | 合成两路结果的办法：每篇得分 = Σ 1/(60+名次)，**只看名次不看分数**，因为两路分数量纲不同 |
| **召回**（recall） | 从全库捞出候选的那一步，目标是「别漏」，一般捞 top-20~50 |
| **精排 / rerank** | 对召回来的候选重新打分排序，目标是「排对」，一般砍到 top-3 |
| **双塔**（bi-encoder） | 问题和文档**各自**编成向量再比相似度。快（文档向量能提前存），但整篇被压成一个向量，细节被稀释 |
| **交叉编码器**（cross-encoder） | 把问题和文档**拼成一条**送进模型，逐字互相看，直接输出一个相关分。准，但每个候选都要跑一次模型，慢 |
| **忠实度**（Faithfulness） | 答案里有几句能在检索到的资料里找到依据 ÷ 总句数。低 = 在编 |

**顺手记两个不算名词但面试会提的：**
- **RAGAS**（RAG 评测框架）：开源 Python 库，喂它「问题+资料+答案」，自动吐 HR/MRR/忠实度这些分
- **LLM-as-a-judge**（大模型当裁判）：RAGAS 背后的做法，让一个 LLM 替你判「这条断言有没有依据」
