### 第 2 步：小心 import 副作用（今天第一个真正的工程点）

写完 `search_kb` 时，你一定会需要一个「全库共用的 retriever」——因为建索引要 2 次 HTTP 请求，
不可能每问一次就重建。最顺手的写法就是把它放顶层：

```python
chunks = []
for d in load_docs():
    chunks.extend(split_text(d["text"], d["source"]))
retriever = Retriever(chunks)        # ← 就是这一行会出事
```

这行在**顶层**，意味着任何人 `import tools` 一次，就发 2 次 HTTP 请求（22 个块分两批）。
明天 `agent.py` 只是 `from tools import TOOLS`，也会被迫等这两次请求——而且网络一挂，import 直接报错，
整个 agent 连启动都启动不了。

改法：**懒加载**（第一次真要用时才建，而且只建一次）。

```python
_RETRIEVER = None

def get_retriever():
    global _RETRIEVER                  # 声明：我要改外面那个全局变量
    if _RETRIEVER is None:             # 第一次进来是 None
        _RETRIEVER = Retriever(_build_chunks())
    return _RETRIEVER
```

**数据快照（这 4 行的值怎么变）**：

| 时刻 | `_RETRIEVER` | 发生了什么 |
| --- | --- | --- |
| import tools 之后 | `None` | 什么都没建，没发请求 |
| 第一次 `get_retriever()` | `None` → `<Retriever object>` | 读 4 篇 → 切 22 块 → 调 2 次 embedding → 建好 FAISS 索引 |
| 第二次 `get_retriever()` | 还是那个对象，不变 | 直接返回，不再建 |

验证：`import tools` 后立刻 `print(tools._RETRIEVER)`，应该是 `None`。

### 第 3 步：三个工具（今天的正事）

规矩（面试问「工具怎么设计」就答这四条）：

| # | 规矩 | 为什么 |
| --- | --- | --- |
| ① | 参数少而明确，1-2 个 | 参数越多模型填错越多，schema 也越贵 |
| ② | 返回值是「小 JSON」，不是 Python 对象 | 模型只能读文本，且要按 JSON 序列化 |
| ③ | 内部异常不往外抛，转成 `{"ok": False, "error": ...}` | 抛异常会打断整个循环；交给模型自己处理更好 |
| ④ | 一定带「来源」 | 不带来源，模型编了你都没法发现 |

| 工具 | 签名 | 返回 |
| --- | --- | --- |
| `search_kb` | `(query: str, top_k: int = 3)` | `{found, hits:[{doc_id, source, text, score}], message}` |
| `calc` | `(expression: str)` | `{ok, result}` / `{ok, error}` |
| `get_doc_meta` | `(doc_id: str)` | `{ok, source, updated, seq_in_doc, text}` |

`search_kb` 里**必须**保留 D6 那个拒答判断（`max_vec < 0.6` → `found=False`）。
但注意：这个 0.6 待会儿会被评测集打脸（见第六节），**今天先别改**，明天连着 Agent 一起改。

### 第 4 步：TOOLS 说明书 + DISPATCH（模型就靠这一段决定调不调）

```python
TOOLS = [ {"type": "function", "function": {"name": ..., "description": ..., "parameters": ...}}, ... ]
DISPATCH = {"search_kb": search_kb, "calc": calc, "get_doc_meta": get_doc_meta}
```

`DISPATCH`（派发表）= 「模型说的名字 → 真正要执行的函数」。模型只会说「我要调 search_kb」，
**真正跑代码的是你这张表**。D1 的 `agent_loop.py` 里就有这张表，同一个东西。

**描述写不好，工具等于没有。** 这是今天最值钱的面试点：

| | 坏描述 | 好描述 |
| --- | --- | --- |
| 内容 | 「搜索知识库」 | 「知识库只包含四类：产品定价 / 差旅报销 / 故障值班 / 硬件保修。问这四类事实必须先调它」 |
| 边界 | 没说 | 「它返回片段，不是完整文档；片段里没有的细节就是没有」 |
| 失败 | 没说 | 「如果返回 found=false，说明知识库里没有，不要用同样的词重复调用」 |
| 后果 | 模型对「北京天气」也去查库，查空还反复查 | 模型知道该查什么、查不到该换词 |

**一句话**：工具描述不是注释，**它就是提示词**。你在教模型「什么时候用我、我怎么坏」。

## 六、基线：这是今天最值钱的 40 分钟（我已经替你跑过一遍了）

跑 `跑基线.py --ref` 会拿到三个数字，然后 `--raw` 再跑一遍做对照。**我实测的结果是这样：**

| 模式 | HR@3 | MRR | 拒答准确率 | 说明 |
| --- | --- | --- | --- | --- |
| 默认（走 `search_kb`，含阈值 0.6） | **66.7%**（10/15） | 0.667 | 80%（4/5） | 有 5 道该答的题被**误拒**了 |
| `--raw`（绕过阈值，只看检索） | **100%**（15/15） | 1.000 | 不评 | 检索内核其实是满分 |

**这 33.3% 的差距，挖出来两个真问题——这两个问题就是 D8 要解决的，也是面试必讲的料：**

### 发现①：拒答阈值 0.6 是拍出来的，它把该答的题也拒了

被误拒的 5 题：Q02（基础版存储上限）、Q08（备用机天数）、Q09（XR-5000 场景）、Q10（XR-3000 差异）、Q14（专业版年付）。

看具体分数就明白了：

| 题 | 最高向量分 | 正确文件在 top3 吗 | 结果 |
| --- | --- | --- | --- |
| Q02 基础版存储上限 | 0.3255 | ✅ 在（3 块全是 01 手册） | 被 0.6 判成「查不到」 |
| Q09 XR-5000 场景 | 0.2536 | ✅ 在（c17 型号块） | 同上 |
| Q14 年付 8 折 | 0.5383 | ✅ 在（价格表块） | 同上 |

**问题不在检索，在阈值。** D5 那个 0.6 是拿 3 道题试出来的，题一多就露馅了。
真正的相似度分布在 0.25~0.74 之间，0.6 卡在中间偏上，一刀切掉一堆正确的。

> 面试怎么说：「我用 20 题评测集跑基线，HR@3 只有 66.7%。我没直接调阈值，而是先关掉拒答再看纯检索——是 100%。所以瓶颈不在检索，在拒答策略是拍脑袋定的。之后我把阈值改成由 LLM 判断资料里到底有没有答案，而不是靠一个分数卡。」

**0.6 到底判错几题、换成别的阈值会不会更好**：跑 `看懂拒答阈值.py`，一条命令出表。
实测结论：0.6 判错 6 题（5 道该答被拒 + Q18 该拒没拒）；扫遍 0.2~0.8，最不坏的是 0.25，**仍然错 3 题**。没有一条线能让错变成 0 —— 这就是发现②。

### 发现②：语义相似 ≠ 有答案（阈值调多少都救不了）

Q18「云图库 Pro 支持导出 PSD 格式吗」—— 语料里**根本没写导出格式**，正确答案是拒答。
但这题的 `max_vec = 0.7365`（比很多该答的题都高），因为它跟「产品定位」那段谈的都是产品能力，语义上很近。

**这种题，阈值往上调就误杀更多正确题，往下调就放过它。单靠分数无解。**

> 这就是「为什么必须是 Agent 不是 RAG 管道」的实证理由：得让模型**把片段读完再判断**
> 「这里面到底有没有回答这个问题」，而不是拿一个相似度数字赌。
> 明天的主循环 + 后天的「够不够」判断节点，就是为这个来的。

## 八、今天的名词表（10 个，每个都要能一句话说清）

> 规矩照旧：先自己写一句话，再对答案。写不出来 = 没会。

| 名词 | 一句话答案 |
| --- | --- |
| **模块**（module） | 一个 `.py` 文件。文件名叫什么，模块就叫什么 |
| **import** | 「执行对方文件 + 把里面的名字打包成一个对象给你」。等价于前端的 `import x from './x.js'` |
| **`if __name__ == "__main__"`** | 只有「我被直接运行」时才执行下面那段；被 import 时不执行。用来把「自检」和「被别人用」分开 |
| **副作用**（side effect） | import 一个模块时，它顶层代码会真的跑。顶层写了联网/建索引，别人一 import 就跟着遭殃 |
| **懒加载**（lazy loading） | 先存 `None`，第一次真要用时才建，之后复用。好处：import 变快、不联网、不报错 |
| **工具描述**（tool description） | 写在 schema 里给模型看的那段话，**它就是提示词**：说清什么时候用、含什么、失败怎么办 |
| **参数表**（parameters / JSON Schema） | 告诉模型这个工具要填哪些字段、什么类型、哪些必填。模型按它生成参数 |
| **评测集**（eval set）/ **标准答案**（gold answer） | 一批「问题 + 人工核对过的正确答案 + 答案该来自哪份文件」。没有它，你只能说「感觉变好了」 |
| **基线**（baseline） | 改造之前先跑一遍分数，之后任何改动都跟它比。没有基线的优化 = 自欺欺人 |
| **跳数**（hop） | 要查几次才够。1 跳 = 一次检索够用；2 跳 = 得换 query 再查（这就是明天「重检」的触发条件） |

**明天伏笔（今天只记名字，不展开）**：主循环（agent loop）、Function Calling 的完整流程、
「够不够」判断节点。这些 D1 你手写过，明天只是把工具换成真的。
